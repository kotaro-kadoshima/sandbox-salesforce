# Spec Delta

## Purpose

MCP クライアントで Salesforce のデータを扱う利用者に、機密情報が含まれる可能性・共有前の確認・本人の責任を、ウィジェットで毎回伝える。ウィジェットを表示できないクライアント（MCP Apps 非対応のクライアント、Slackbot など）への伝達は対象外とする。

## ADDED Requirements

### Requirement: すべての応答に注意喚起を含める

カスタム MCP サーバーの 3 つのツールは、成功・0 件・入力の拒否・エラーのどの応答にも、条件分岐なしで注意喚起を含める（SHALL）。結果の内容・件数・ユーザー・クライアントによって注意喚起を省略したり、出し分けたりしてはならない（MUST NOT）。

#### Scenario: 結果があるときに注意喚起が含まれる

- **WHEN** 3 つのツールのいずれかが 1 件以上のレコードを返す
- **THEN** 応答に注意喚起が含まれる

#### Scenario: 0 件のときも注意喚起が含まれる

- **WHEN** 3 つのツールのいずれかが 0 件の結果を返す
- **THEN** 応答に注意喚起が含まれる

#### Scenario: 拒否やエラーのときも注意喚起が含まれる

- **WHEN** SELECT 以外の SOQL や不正な入力を渡す、または権限エラーやクエリエラーが起きる
- **THEN** 失敗の応答に注意喚起が含まれる

### Requirement: 注意喚起で 3 つの内容を伝える

注意喚起は、見出しに加えて次の 3 つの内容を伝える（SHALL）。

1. Salesforce には機密情報が含まれている可能性があること
2. 内容を共有・転記する際は、共有先と内容を必ず確認すること
3. 情報の取り扱いの責任は利用者本人にあること

#### Scenario: 注意喚起に 3 つの内容がそろっている

- **WHEN** 3 つのツールのいずれかの応答を受け取る
- **THEN** 注意喚起には見出しと、上記 3 つの内容がそれぞれ含まれる

### Requirement: MCP Apps 対応クライアントでウィジェットとして表示する

3 つのツールは、MCP Apps に対応したクライアント（Claude Desktop など）で、注意喚起をウィジェットとして表示する（SHALL）。ウィジェットに表示するのは注意喚起だけとし、レコードの内容は表示しない。

#### Scenario: Claude Desktop にウィジェットが表示される

- **WHEN** Claude Desktop から 3 つのツールのそれぞれを、入力 1 件で実行する
- **THEN** どのツールでも、見出しと 3 つの内容を含む注意喚起のウィジェットが表示される

#### Scenario: エラーのときもウィジェットが表示される

- **WHEN** Claude Desktop から SELECT 以外の SOQL を渡して SOQL 検索ツールを実行する
- **THEN** 注意喚起のウィジェットが表示される

### Requirement: モデルに注意喚起の伝達を指示しない

注意喚起はウィジェットで届け、MCP クライアントのモデルにテキストで伝えるよう指示しない（SHALL）。ツールの説明は sobject-reads の同名のツールと同じにし、ツールの説明と出力項目の説明に、注意喚起を利用者へ伝えるよう求める文を含めてはならない（MUST NOT）。ウィジェットとモデルの回答の両方に注意喚起が出る、二重の表示を避けるため。

#### Scenario: ツールの説明が sobject-reads と同じである

- **WHEN** MCP クライアントがツール一覧を取得する
- **THEN** 3 つのツールの説明は sobject-reads の同名のツールの説明と同じで、注意喚起の伝達を求める文が含まれない

### Requirement: 注意喚起の文言をコードを変えずに差し替える

注意喚起の文言は実装に直接書かず、組織の設定として管理する（SHALL）。管理者が文言を変更したら、コードの変更なしに、次の呼び出しからウィジェットに新しい文言が反映される（SHALL）。

#### Scenario: 文言を変更するとウィジェットに反映される

- **GIVEN** 管理者が注意喚起の文言を変更した
- **WHEN** 利用者がツールを実行する
- **THEN** ウィジェットに、変更後の文言が表示される
